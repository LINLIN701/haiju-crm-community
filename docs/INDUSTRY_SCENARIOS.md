# 多行业应用：先维护关系，再扩展行业业务

适用社区版V1.01.01。[返回首页](../README.md) · [使用教程](USER_GUIDE.md)

本版有8类内置行业填写提示，也允许输入自定义行业。所有行业使用同一套真实关系档案和沟通记录；行业切换不会自动改写历史资料、生成AI结论或触发外部业务。

## 可以实际使用的关系维护流程

1. 新增个人或机构档案，选择行业，记录所属机构、职务和联系渠道。
2. 按事实标注关系类型（客户、合作伙伴、转介绍人等）、当前阶段与关注事项。
3. 每次沟通后记录实际时间、渠道和摘要，安排下一次联系。
4. 在关系概览处理到期回访，或按行业/阶段筛选档案继续推进。
5. 在中文操作日志查证保存动作；需要迁移资料时导出CSV，完整备份使用数据库备份。

| 场景 | 关注事项可记录的内容 | 跟进应用示例 | 不包含的行业核心系统 |
| --- | --- | --- | --- |
| 保险 | 已表达的保障咨询、服务事项、续期沟通约定 | 服务回访、续期前联系、补充问题确认 | 保单台账、核保、理赔、保险资格判断 |
| 银行 | 个人/企业客户的服务需求、合作范围、材料沟通进展 | 服务回访、企业拜访、沟通预约 | 核心账户、授信审批、征信、支付、适当性评估 |
| 房地产 | 客户已表达的区域需求、购租意向、委托沟通、带看反馈 | 带看后回访、业主沟通、渠道维护 | 房源库存、交易合同、资金监管、产权核验 |
| 企业服务 | 企业名称、联系人职务、采购诉求、方案进展 | 方案会、项目回访、合作续约沟通 | 独立商机管道、合同/发票/回款管理 |
| 教育培训 | 课程咨询、预约沟通、服务反馈 | 咨询回访、课程服务与续学沟通 | 教务排课、成绩档案、招生审批 |
| 专业服务 | 项目诉求、服务范围、沟通结论 | 咨询/设计等项目联系与服务回访 | 机密案卷、专业审批与业务资格判断 |
| 零售 | 商品偏好、售后事项、已约定回访 | 售后回访和商品咨询；消费记录按需启用 | 进销存、收银、完整订单与退款 |
| 通用/自定义行业 | 联系缘由、共同事项、合作关系与下一步 | 合作伙伴、转介绍、供应商及其他长期联系人维护 | 自动关系图谱、复杂项目编排、多人权限 |

这些是基于已实现功能的使用方式，不是行业产品验收清单。静态提示明确标为“非AI”，不会替代从业判断或外部模型。

## 三个虚构练习

- **保险服务**：林小禾（示例），行业保险、关系类型客户、阶段持续维护；关注事项填“已约定续期前沟通服务事项”。保存一条电话跟进并填写下一次联系时间。
- **银行企业服务**：陈知夏（示例），所属机构“示例企业”、职务“项目联系人”，行业银行、阶段需求沟通；关注事项填“了解服务范围，约定下周沟通”。不记录账户、余额或征信。
- **地产渠道**：周明远（示例），行业房地产、关系类型合作伙伴、阶段方案跟进；关注事项填“讨论带看协作安排”。记录面谈摘要与下次回访。

## 必须理解的边界

- “所属机构”是可查询的文字字段，不是组织主数据、机构权限边界或人员关系图谱。
- “关系阶段”由用户手工维护，不自动创建商机、审批、合同或业务状态机；暂缓联系也不会自动取消已有提醒，需新增跟进并将下一次时间留空。
- 每个客户当前有效提醒取最后新增的一条跟进，不是多事件日历。续期、带看、合作回访等同时存在多个日期时，本版不能承诺独立追踪每个事项。
- 消费仅用于已发生的消费记录。保额、贷款额度、资产余额、房屋意向价格是不同业务含义，不应填入消费来求和。
- 社区版为单管理员权限范围，不适合据此直接开展需要精细授权、审批留痕和行业合规保障的机构级生产业务；部署者应先完成相应评估。
- 只录入必要且有权处理的资料，不向公开Issue或模型提交证件、账户、征信、健康、未成年人等敏感信息。本版不提供这些行业专属敏感资料的治理能力。
